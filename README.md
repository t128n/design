# @t128n/ui

The t128n design system: semantic tokens, Svelte 5 components and reference
views for calm, dense product interfaces. The source of truth is
[`DESIGN.md`](./DESIGN.md); the package implements it.

## Install

```sh
npm install @t128n/ui
```

`@t128n/ui` is a Svelte 5 library. `svelte` is the only peer dependency.

## Quick start

Load the generated tokens once, then optionally the base reset and layout
skeletons:

```js
import "@t128n/ui/styles.css"; // tokens for both themes
import "@t128n/ui/base.css"; // reset, focus ring, body type
import "@t128n/ui/layouts.css"; // .t128n-page, .t128n-app-shell, ...
```

Wrap the interface in `Theme` to scope a theme, density and hairline mode:

```svelte
<script>
  import { Button, Theme } from "@t128n/ui";
</script>

<Theme theme="dark" density="comfortable" lines="faint">
  <Button variant="primary">New issue</Button>
</Theme>
```

### Theme, density and lines

`Theme` writes three container attributes. Components read only their tokens,
so no component branches on density or theme.

| Prop | Values | Default | Effect |
|---|---|---|---|
| `theme` | `light`, `dark` | `light` | Switches the semantic colour set. `tokens.css` also follows `prefers-color-scheme` when no `data-theme` is set. |
| `density` | `compact`, `default`, `comfortable` | `default` | Sets `--row-h`, `--row-h-sm` and `--control-h`. Comfortable is the coarse-pointer default. |
| `lines` | `none`, `faint`, `visible` | `faint` | Sets the hairline alpha. Lines are never the only separator. |

The same attributes work on any container, and on `<html>` for a whole app.

## Components

| Family | Exports |
|---|---|
| Actions | `Button`, `IconButton` |
| Forms | `Field`, `Input`, `Textarea`, `Select`, `Checkbox`, `Radio`, `Switch` |
| Search | `SearchField`, `Combobox`, `DatePicker` |
| Navigation | `Sidebar`, `Breadcrumbs`, `Tabs`, `SegmentedControl`, `Tree`, `Pagination` |
| Shell | `AppShell`, `Header`, `Toolbar`, `SectionHeader` |
| Data display | `Table`, `ListRow`, `GroupHeader`, `PropertyRow`, `Toggle`, `BoardCard`, `GalleryCard` |
| Chips and status | `Tag`, `Badge`, `Avatar`, `Progress`, `StatCard` |
| Overlays | `Menu`, `Popover`, `Dialog`, `SlashMenu`, `CommandPalette` |
| Feedback | `Tooltip`, `Banner`, `InlineError`, `EmptyState`, `Skeleton` |
| Documents | `Chart`, `CodeBlock`, `Callout`, `CalendarGrid` |
| Foundation | `Theme`, `Icon` |

Every component ships scoped styles, a test and a Storybook story with prop
controls. Icon-only controls take a `label`; every input belongs in a `Field`.

## Views

These are reference compositions, also exported for reuse:

| View | Export | Structure |
|---|---|---|
| Issues | `Issues` | Grouped list and detail pane |
| Board | `Board` | Horizontally scrolling status columns |
| Table database | `DatabaseTable` | Toolbar, table, footer count |
| Document page | `DocumentPage` | Reading column with property rows and blocks |
| Settings | `Settings` | Section nav, label and control rows, danger zone |
| Inbox | `Inbox` | Tabs, unread rows, hover-revealed actions |
| Overview | `Overview` | Stats, one-series chart, activity, projects table |
| Calendar | `CalendarView` | Month grid with events |
| Empty workspace | `EmptyWorkspace` | One primary next action |
| Error | `ErrorView` | System banner and retry |

View stories live in `src/stories/views/`; layout skeleton details are in
[`docs/layouts.md`](./docs/layouts.md).

## Scripts

| Script | Purpose |
|---|---|
| `npm run dev` | Vite dev server |
| `npm test` | Vitest unit and package tests |
| `npm run check` | `svelte-check` over source and stories |
| `npm run storybook` | Storybook with theme, density and lines toolbars |
| `npm run build` | Vite library build |
| `npm run package` | Generate the barrel, build `dist/` with `.svelte` sources and types, prune test output, copy `tokens.css` and `layouts.css` |

`src/lib/index.ts` is generated by `scripts/build-index.mjs`. Edit a component
or its folder `index.ts`, never the barrel. Package output:

- `dist/index.js` and `dist/index.d.ts` — the barrel and its types
- `dist/components/**`, `dist/views/**`, `dist/theme/**`, `dist/icons/**`
- `dist/tokens.css` — generated semantic tokens
- `dist/layouts.css` — the layout skeletons
- `dist/styles/base.css` — reset and base type

## Contributing

Read `DESIGN.md` before changing a component, especially sections 6 (shared
behaviour), 10 (Always and Never) and 13 (verification checklist). Use semantic
tokens only, keep every state, and add or update the story with the change.
