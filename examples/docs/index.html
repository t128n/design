Color

The t128n palette is derived from Oxocarbon (base16), with every value pinned in the design system. Applications consume role tokens such as canvas, surface, and text-primary; they never reference base16 slot numbers or raw hex values. This page documents the roles, the contrast floor they meet, and the colors defined outside the scheme.

Roles

Role tokens name a job, not a position in the palette. canvas is the page, surface is a blocked region such as a sidebar or code block, and surface-2 is the stronger fill used for table headers and hover. surface-3 is the quieter selected-row fill used by vertical navigation. Borders carry structure, text roles carry hierarchy, and primary marks the wordmark, action, selection, focus, and current state.

Keep the assignment literal: a component asks for the named role, never for a raw hex value or a base16 slot. The values below are the source of truth for both themes.

Representative roles with their light and dark values.

Role Light Dark Use
canvas #FFFFFF #161616 Page background
surface #F2F4F8 #262626 Sidebar, stripes, blocked regions
surface-2 #DDE1E6 #393939 Table headers, hover, active, disabled
surface-3 #E8EBEE #303030 Selected vertical-navigation rows
primary #0F62FE #33B1FF Wordmark, actions, selection, focus
on-primary #FFFFFF #161616 Text on primary fills
error #DA1E28 #FF8389 Error text, borders, fills
success #0E6027 #42BE65 Success text and icons

Use border-strong for interactive boundaries and border-subtle for structural separation. text-muted is limited to placeholders and helper text on canvas and surface; text-disabled is reserved for disabled labels and never for information a user needs.

The raw palette is published in the Oxocarbon base16 repository. Treat it as the origin of the values, not as an interface API: base08 is cyan in dark theme and pink in light theme, so a slot number cannot describe a stable role.

Contrast

Contrast is measured against the canvas in both themes before a role is accepted. Three thresholds apply:

  1. Body text reaches at least 4.5:1 against its background.
  2. Large text at 20px and 600 weight reaches at least 3:1.
  3. Interactive boundaries and focus indicators reach at least 3:1.

The verified ratio for primary is 5.00:1 in light theme and 7.65:1 in dark theme. text-primary measures 18.10:1 and 16.43:1. Ratios are recorded against canvas; a color moved to another surface must be checked again.

Primary text must not sit on surface-2 or surface-3. The combinations measure 3.81:1 and 4.18:1 in light theme, below the 4.5:1 body threshold, so both stay fills and boundaries — never a text background for primary.

Use text-primary or text-secondary on surface-2 or surface-3, and reserve primary for text on canvas or surface.

Selection

Selected text uses the selection overlay: primary at 12% opacity in light theme and 16% in dark theme. text-primary stays unchanged, and the overlay tints canvas, surface, surface-2, and surface-3 without a separate token for each context.

Persistent selection uses the 2px primary indicator. Horizontal navigation spans the item with the underline and sits flush with the app-bar rule, with no fill. Vertical navigation rows use the surface-3 selected fill, so the indicator, label, and row read as one object; the vertical indicator runs the full row height at the leading edge, and other selected rows stay unfilled. Never invert text or fill a row with solid primary, so selection never depends on color alone.

A Palette Without Red

Oxocarbon contains no red.

The base16 slot base08 is cyan in dark theme and pink in light theme, so error, warning, and success are defined outside the scheme and contrast-tested on their own. Do not remap them back to slot names in either theme.

Status always pairs an icon with text. Status colors are text and icons; the only solid status fill is the danger button, error with on-error. Icon-only status is not acceptable.

Tokens in Practice

Define each role once per theme, then let components read only the role name. The four roles below are enough for a neutral reading surface; copy the block into your theme layer and add the rest from the table.

theme.css 
:root {
  --canvas: #FFFFFF;
  --text-primary: #161616;
  --primary: #0F62FE;
  --border-subtle: #DDE1E6;
}

[data-theme="dark"] {
  --canvas: #161616;
  --text-primary: #F2F4F8;
  --primary: #33B1FF;
  --border-subtle: #393939;
}

Keep the token names stable across themes. A component should never branch on the theme or read a base16 slot directly; if a new surface needs a color, add the role here first.
